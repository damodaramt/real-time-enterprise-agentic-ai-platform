# pgvector

## Introduction

pgvector is a PostgreSQL extension that enables vector similarity search directly inside PostgreSQL. It allows machine learning embeddings to be stored and queried efficiently, making PostgreSQL suitable for Retrieval-Augmented Generation (RAG) applications.

This project uses pgvector to store embedding vectors generated from enterprise documents and perform semantic search.

---

# Why pgvector?

Traditional SQL databases perform exact matching.

Example:

SELECT * FROM documents
WHERE title = 'Docker';

Semantic search requires finding documents with similar meaning rather than exact text matches.

pgvector enables:

* Vector storage
* Cosine similarity search
* Euclidean distance search
* Inner product search
* Approximate Nearest Neighbor (ANN) indexing

# Installation

Install pgvector extension inside PostgreSQL.

Example:

CREATE EXTENSION IF NOT EXISTS vector;

---

# Vector Data Type

pgvector introduces the VECTOR data type.

Example:

embedding VECTOR(384)

384 represents the embedding dimension generated by the all-MiniLM-L6-v2 model.

# Similarity Metrics

## Cosine Similarity

Most commonly used for text embeddings.

Measures the angle between vectors.

Smaller distance indicates higher similarity.

---

## Euclidean Distance

Measures the straight-line distance between vectors.

---

## Inner Product

Measures vector similarity using dot products.

Useful for normalized embeddings.

---

# Example Query

Retrieve the five closest document chunks.

SELECT

id,

content,

embedding <=> query_vector

FROM documents

ORDER BY embedding <=> query_vector

LIMIT 5;

---

# Vector Dimensions

The embedding dimension must match the embedding model.

Examples

all-MiniLM-L6-v2

384 dimensions

OpenAI text-embedding-3-small

1536 dimensions

Changing embedding models requires regenerating all stored embeddings.
